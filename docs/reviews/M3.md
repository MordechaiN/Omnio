# M3 Self-Review — Core Platform Services

**Date:** 2026-07-17 · **Verdict: the platform substrate is production-quality; proceed to M4.** Debts below carry a milestone owner — nothing here is silent.

## What holds up

- **Postgres is the source of truth; Redis/BullMQ is only transport.** The seven core tables ([01 §5](../architecture/01-system-overview.md)) exist as designed, jobs are rows whose lifecycle the worker mutates, and the queue payload is a bare `{jobId}`. There is no state that lives only in Redis.
- **Auth is secure-by-default.** A global `SessionGuard` authenticates every route unless explicitly `@Public`; Argon2id hashing, opaque sessions (only the SHA-256 stored), rotation on login, and login-enumeration resistance via a decoy hash. `OMNIO_AUTH=none` still provisions a real admin row and refuses a non-local bind unless force-flagged.
- **Uploads are validated in a single streaming pass.** Size is capped as bytes arrive, the SHA-256 is computed inline, and the leading bytes are magic-sniffed — a declared extension that contradicts the bytes is rejected, and partial objects are deleted on any failure. Storage keys are generated ULIDs; downloads are always `attachment`.
- **The three security guarantees are mechanical, not aspirational.** Helmet CSP (`default-src 'none'` for the JSON/api surface), same-origin CSRF enforcement on mutations, and Redis-backed tiered rate limiting (429 + `Retry-After`, fail-open). Config refuses startup on an invalid environment or a dev secret in production.
- **Storage and jobs are behind small interfaces.** `StorageDriver` (fs impl, S3/MinIO a drop-in later) and `@omnio/jobs` (queue name, payload, SSE progress) keep api and worker sharing one contract without importing each other.

## Weaknesses found, and their disposition

1. **The worker's job execution and TTL sweep are unit-tested, but the api integration test drives an in-process copy of that logic** (`test/harness.ts`), not the worker app's own `processor.ts`/`sweeper.ts` — the module-boundary law forbids api importing worker. _Disposition:_ once M4 introduces the module SDK, the job runtime moves into a shared, independently-testable surface; until then the two paths are kept byte-identical and both covered.
2. **Migrations run via `prisma migrate deploy` shelled from `@omnio/db`**, which pulls the Prisma CLI into the runtime image. _Disposition:_ acceptable for v1 (advisory-locked, multi-replica-safe); revisit with a slimmer migration runner during the M9 image-hardening pass.
3. **Integration tests require Docker and self-skip without it.** They run in a dedicated CI job, not the default unit suite. _Disposition:_ intentional — keeps `pnpm test` fast and hermetic; the CI job is the gate.
4. **`file-type@16` (CJS) is pinned** because newer majors are ESM-only and the api compiles to CommonJS. _Disposition:_ fine for the M3 validation set; reassess when the viewer (M6) needs richer detection.
5. **CSRF requires an `Origin` header on every mutation**, which rejects non-browser clients. _Disposition:_ correct for the v1 single-admin SPA (cookie-only auth); revisit if/when a token-authenticated API lane appears (post-v1).
6. **The analytics sink and settings are minimal** — a gated `ToolEvent` writer and instance-boolean reader. Not debt — staging; full settings CRUD and the admin analytics viewer are M5/M9.

## Architecture confirmations

No regrets on: contract-first ts-rest (the typed surface grew four routers with zero drift), SSE over WebSockets for progress (simple, proxy-friendly, one Redis channel), the storage-driver abstraction from day one, and Postgres-as-truth with BullMQ as pure transport. Binary transfer deliberately sits outside ts-rest as raw streaming routes — the JSON contract models everything else, and the global guard still secures them.
