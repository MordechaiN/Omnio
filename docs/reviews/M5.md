# M5 Self-Review — Workspace Experience

**Date:** 2026-07-17 · **Verdict: Omnio now feels like a workspace, not a scaffold. The client-first experience is alpha-quality; the API-backed workflow is the remaining slice.** Debts carry an owner.

## What holds up

- **The workspace leads with tools.** The home opens with a real tool launcher (registry-driven cards) above the categories, and returning users see their pinned and recently used tools first. The first 30 seconds say "workspace".
- **File drop is delightful and private.** Drag a file anywhere → an inviting full-window overlay ("stays on your device — nothing is uploaded") → an action sheet offering **View** plus any tool that declares it accepts the type (from `capabilities.json`).
- **Universal viewer foundation.** Images, PDF, text/code, audio, and video render inline from in-memory object URLs, with a graceful no-preview state, loading spinner, and object-URL cleanup — no upload, no round-trip.
- **Personal and consistent.** Favorites + recents persist in schema-versioned localStorage via a `useSyncExternalStore` singleton (no new deps, no provider), synced across every surface; one `ToolCard`/`ToolGrid` renders tools identically everywhere.
- **Polished states and inputs.** Empty states, a route-level tool skeleton, the "/" quick-open shortcut, responsive grids, and RTL — all covered. The full Playwright suite (16 tests incl. axe a11y on the new home, RTL, and three new workspace flows) is green.

## Weaknesses found, and their disposition

1. **No API-backed workflow yet.** Auth UI (first-run setup / login), upload, the jobs tray, SSE progress, and recent _server_ files are not wired — the web does not yet call the api. _Disposition:_ this is the next vertical (a ts-rest client + TanStack Query + auth screens + upload/jobs). Browser-tier tools and the viewer are fully usable without it; worker-tier actions currently deep-link to the tool page. Owner: **M5 continuation / M6**.
2. **Worker-tier file actions can't run from the sheet.** Selecting a worker action (e.g. uppercase) navigates to the tool page, whose surface is an M5 placeholder until upload lands. _Disposition:_ completes with #1.
3. **Drop → action sheet has no e2e.** Drag-and-drop is awkward to drive in Playwright; the flow is covered by unit-level detection + manual verification. _Disposition:_ add a synthetic drop test with #1.
4. **Fuzzy search is cmdk's built-in scorer.** Good now; MiniSearch stays an M7 data swap (registry-shaped entries), per `docs/TECH_DEBT.md`.

## Architecture confirmations

No regrets on: the shell owning providers (palette + file-drop) so the frame never reloads, localStorage-with-schema-version for client prefs (§4) via `useSyncExternalStore` rather than a store dependency, the registry as the single source for launcher/search/capabilities, and rendering personal sections empty on the server so there is no hydration flash. Logical CSS properties kept every new surface RTL-correct with zero extra work.
