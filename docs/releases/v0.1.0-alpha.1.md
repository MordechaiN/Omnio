# Omnio v0.1.0-alpha.1

**First public alpha — 2026-07-18**

Omnio becomes a professionally versioned, releasable product: a self-hosted
personal workspace with tools that run entirely on your device, an end-to-end
worker pipeline, and a permanent release-management system.

> **Alpha.** Interfaces and data shapes may change between pre-releases. Personal
> mode has no authentication by design — do not expose an instance holding data
> you are unwilling to make public.

## Platform

pnpm + Turborepo monorepo with a Next.js web app, a NestJS api, and a BullMQ
worker, over PostgreSQL and Redis with Prisma. A typed ts-rest contract is the
single web↔api boundary. A design system (tokens, themes, RTL) underpins the UI,
and `modgen` auto-discovers modules to generate the search index, category pages,
command-palette entries, and dependency wiring — no tool is ever hand-registered.

## Infrastructure

- Semantic Versioning with documented pre-release stages (alpha → beta → rc →
  stable → patch); the root `package.json` version is the single source of truth.
- Every build embeds version, git commit, git branch, build timestamp, and build
  number, injected from git at build time — never hand-maintained.
- `GET /api/version` reports the running deployment; a footer version badge, an
  About page, and a Changelog page surface it in the UI.
- `CHANGELOG.md` (Keep a Changelog) plus a documented commit → push → build →
  deploy → verify → tag → release workflow.

## Deployment

- Cloudflare Tunnel is the only ingress: Internet → Tunnel → `127.0.0.1:4200`
  (web). The api and worker are internal Docker services, never publicly exposed.
- Docker Compose is the deployment mechanism; the CLI is the management
  interface. Oracle VPS is the canonical runtime; GitHub is the canonical source.
- Deployment verification confirms Oracle and GitHub report identical versions.

## Authentication changes

Deployment mode now defaults to **personal**: no authentication, no login, no
setup wizard — immediate use as a self-hosted personal workspace. Set
`OMNIO_MODE=multi-user` for the original single-admin model with password login,
sessions, and the stricter security posture.

## Personal Mode

The default experience. A returning user lands directly in the workspace with
their pinned and recent tools; there is no account to manage and no session to
sign out of. This instance runs in personal mode and is publicly reachable with
no authentication by explicit operator decision.

## Browser tools

36 tools across 31 modules, all on-device, in English and Hebrew with full RTL:

- **Developer** — JSON format, YAML↔JSON, CSV↔JSON, JWT decode, Base64, URL
  encode, HTML entities, text↔binary, number base, UUID.
- **Text** — case convert, Lorem Ipsum, text stats, text diff, slugify, regex
  tester, Markdown preview, line tools.
- **Security** — hash generator, password generator.
- **Utilities** — unit / color / timestamp / date / Roman converters, WCAG
  contrast checker, CSS gradient builder, BMI, random numbers.
- **Finance** — loan, VAT, percentage, tip.
- **Networking** — CIDR / subnet calculator.

Each ships framework-free logic with unit tests, an accessible ToolShell surface,
and a "runs on your device" guarantee.

## Known limitations

- Alpha stability: expect changes between pre-releases.
- Personal mode has no authentication — this is intentional, not a gap.
- Worker-tier tools (image / PDF / media processing) are not part of this release.
- No automated database backups are configured yet.
