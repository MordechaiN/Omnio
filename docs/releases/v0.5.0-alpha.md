# Omnio v0.5.0-alpha

**Your files have a home — 2026-07-24**

Until now every tool was an island: a file went in, a result came out, and
nothing was remembered. This release introduces the File Workspace, so files
persist and tools become actions performed on them.

> **Alpha.** Interfaces and data shapes may change between pre-releases. Personal
> mode has no authentication by design — do not expose an instance holding data
> you are unwilling to make public.

## Files

Everything dropped into Omnio is kept and appears in **Files**: a thumbnail grid
with the selection conventions of a desktop file manager — click to select,
Shift-click for a range, Ctrl/Cmd-click to add. Search by name, filter by type,
sort by recency, size, name or date added. Pin what matters; pinned files lead
every sort and are never evicted.

The grid is virtualized: only the rows intersecting the viewport are mounted, so
a workspace of thousands of files costs what one of twenty costs.

## The Inspector

A permanent panel, not a dialog. Selecting a file immediately shows its preview,
type, size, dates, tags and collections — plus the part that makes it a
workspace rather than a folder: **where the file came from**, what has been made
from it, its siblings, and its complete history.

There is no loading state on this path by design. File metadata is small, so the
whole set is held in memory and served synchronously; only bytes and thumbnails
load lazily.

## Tools compose

Anything a tool produces lands back in the workspace, so one tool's output is
ready for the next without a round trip through the downloads folder. Every PDF
tool downloads through one shared helper, so all 35 adopted this at once.

Opening a workspace file hands the tool a real `File` through the same channel a
drop zone uses — which is why every existing tool accepts workspace files
without having been modified.

## Keyboard

Space for Quick Look, Enter or double-click to open in the best-matching tool,
arrow keys to move, Ctrl/Cmd+A to select all, Delete to remove, Ctrl/Cmd+Z to
undo a delete, Escape to clear.

## How it is stored

Bytes live in the browser's Origin Private File System, addressed by the SHA-256
of their content; metadata, tags, collections, history and thumbnails live in
IndexedDB. Content addressing means identical files are stored exactly once and
duplicate detection is exact rather than a guess based on names. A stored blob is
removed only when no record still references it.

Nothing is uploaded. The workspace is local-first in the strict sense: the server
is used only where a specific tool already required it.

## Verified

- 33 unit tests over the workspace model (search, sorting, duplicates,
  relationships, eviction).
- 13 browser tests driving real OPFS and IndexedDB, including persistence across
  a reload and a tool-output round trip.
- 51 browser tests across the whole suite.

Two bugs were found by those browser tests that unit tests could not have
caught: a `File` handed back by OPFS is a live handle rather than a snapshot, so
undo-after-delete restored nothing; and the Inspector referenced a date format
that did not exist.

## Known limitations

- **Local to this browser, on this device.** Nothing is synced, and clearing
  browser data clears the workspace. Exported copies remain the real backup, and
  the interface does not pretend otherwise.
- **Private browsing** generally forbids persistent storage. Omnio detects this
  and says so plainly; tools keep working, files simply are not remembered.
- **No folders.** Tags, collections and search cover the same ground; folders may
  arrive later as a saved search.
- **No full-text search inside documents.** Search covers names, types and tags.
